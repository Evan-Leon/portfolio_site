Prompt-heus

Builds and serves versioned, LLM-refined system prompts for a fleet of AI personas.

Problem

Every app in the EVOsystem runs on an AI persona, and each persona's system prompt lived as a copy-pasted string inside whichever codebase used it. Nothing versioned them and nothing reviewed them, so changing one gave no way to tell which app had just started behaving differently.

Solution

Prompt-heus is the one place an AIOS is defined. A three-stage builder turns identity fields into a draft prompt, refines it in conversation with Claude, then gates it on a quality assessment before approval. Approved versions are immutable, and a Registry API serves the active prompt to every consuming app over the shared Docker network.

Tech Stack

FastAPI PostgreSQL React 19 TypeScript TanStack Query Registry API

Key Features

AIOS Registry

Every persona in one list with its role, approved version and last change

Immutable Version History

Approving supersedes the previous prompt; old versions stay readable and are never edited

Three-Stage Builder

Intake the identity fields, refine the draft with Claude, then pass a quality gate before approving

Persona Controls, Not Prose

Trait chips, register and formality sliders, and always/never anchors compile into the prompt
