## What the meta-prompt requires (contract the seeds must meet)

- Throwaway store from the app's OWN migrations, never a copy of real data; app started against it with an uncommitted compose override or env var; teardown = stop app, drop store, restart on normal config, read back one known real record, prove store gone (L352-361, L750-760).
- Seed committed as `scripts/showcase_demo.*` in the app repo with fixture and tests; the only allowed app-repo writes (L190-195). Idempotent, recognisable id prefix, reset on rerun (L392-393).
- Seed through the app's OWN signup route / services where possible; check quick-add-only serializers; backdate `created_at` with per-row UPDATE; seeded rows must pass the app's own health arithmetic (L394-416).
- If an app cannot be pointed at a throwaway store without a code change: STOP and ask (L360-361).
- Gate (gate-run.sh) is only for Postgres apps that seeded into a REAL DB (leonsbudget, the-classic, chudios, co-host, co-host-chud, co-author, mind-palace neo4j). With throwaway stores it should be unnecessary; it stays as the fallback and as the pattern for fail-closed guards (container+project pin, DB name pin).
- Prior runs (runlog / Coverage): all 16 EVOsystem apps were captured against the real dev DB. Seeded: the-classic, LeonsBudget, jourNOW, graces-tree, co-author, co-host, chudios, mind-palace, chud (conv 7206 retained), app-dash (one retained log row). ## Cross-cutting observations

1. Postgres apps: a throwaway is just `CREATE DATABASE x_showcase` on infra-postgres-1 as `postgres`, run the app's own migrate against it with the env override, seed, point the app container at it, drop with `WITH (FORCE)`. This works for 12 of the 16 apps. Hard cases: the-classic (second Supabase project, ports, frontend build-time URL), mind-palace (second Neo4j container), chunk-norris (Qdrant collections outside Postgres), and files (chudios recordings volume, voice-trainer voice-clips volume, graces-tree/jourNOW R2 keys: seed no media).
2. Auto-migrate is inconsistent: auto at start for graces-tree, co-author, chudios, co-host, chunk-norris, logson, chud; NOT for LeonsBudget, jourNOW, NomNoms, Prompt-heus, voice-trainer, app-dash. The seed script should run the app's migrate step itself (or document it) and never rely on the app container starting.
3. Dangerous side effect of auto-migrate: `docker compose up` with the normal URL migrates the real DB, so use `docker compose run --rm --no-deps -e DATABASE_URL=...` for the throwaway.
4. Proposed seed contract (one for all): `scripts/showcase_demo.py` (Django apps: a `manage.py shell`-compatible or standalone script using `django.setup()`; FastAPI/asyncpg apps: standalone `asyncio`), plus `scripts/showcase_demo_fixture.json` if data is static. CLI `seed|reset|teardown-check`. Rules: (a) refuse to run unless the target DB name ends in `_showcase` (parse `DATABASE_URL`/`DB_NAME`/`POSTGRES_URL`/`NEO4J_URI`), the pattern gate-run.sh and chud's gate_safety.py:184 already use; (b) idempotent: delete-and-recreate by prefix inside the throwaway only; (c) recognisable ids/emails (`demo@example.com`, `dddddddd-` UUID prefix); (d) hand-written fictional data in a committed fixture so retakes are identical (no Faker needed; deterministic beats fresh random for a clip; if Faker is wanted add it with a fixed seed and as dev dependency only where absent); (e) never call external effects: no R2, Whisper, CHUD, Chatterbox, Temporal, LLM; insert terminal-state rows directly; (f) print every created id; (g) a test that runs the seed against the app's `_test` DB and asserts the fields the UI renders are non-empty and computed fields read clean.
5. A meta-prompt orchestration helper (infra) would remove repeated boilerplate: `showcase-store.sh <app> up|down` doing CREATE DATABASE, migrate, compose override, and teardown read-back, reusing gate-run.sh's container+project pinning.

## Risks

- Cross-app bleed: swapping Prompt-heus, app-dash, logson or chud DB changes what other live apps show (CHUD, chunk-norris, voice-trainer, logson all read Prompt-heus; CHUD reads app-dash and logson; logson receives fleet telemetry). Prefer a second instance on another port for logson; for Prompt-heus either stub or seed matching ids.
- Shared Temporal queue (voice-trainer, chud): a second instance's workflows are picked up by the live worker on the live DB.
- Host-run worker for chud (`chud-temporal-worker.service`) does not read compose env; must be stopped or given a drop-in, else schedules write elsewhere.
- Panels fed by the filesystem or other services (app-dash `EVOSYSTEM_ROOT`, chud session-log context and app health, mind-palace and co-host health probes) still show live data; the throwaway DB does not make those frames safe. Needs redaction or fixture mounts, so STEP 1's data check still applies.
- Write effects that fire external systems when seeding through APIs: co-host freeze -> CHUD job; chudios `POST /content_items` -> CHUD; co-author `create_and_submit`; voice-trainer ingest/auditions/clips -> Temporal; LeonsBudget `.delay()`; NomNoms imports -> Celery + CHUD; chud chat -> 27B model (BSOD history).
- Real-name leakage in reusable seeds: graces-tree `seeds/people.py` and Prompt-heus `docs/*-output.json` contain real content.
- Two stale-risk facts: the survey's file:line cites came from sub-agents and several were not independently verified (e.g. graces-tree viewer endpoints `AllowAny`; whether LeonsBudget `seed_demo` names are all fictional; whether `docker compose run -e` overrides cleanly). Second Supabase project via `--workdir` is unverified.
- Credentials: jourNOW `.env.dev` and `.env.copy` are tracked in git; the seed must not read or echo them.
- Seeds go stale as schemas evolve; the test-against-`_test`-DB check (rule g) is the guard. Stale tech pills on four pages (runlog) is a separate known task.
